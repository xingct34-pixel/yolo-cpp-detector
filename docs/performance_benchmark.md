# YOLO C++ 推理部署性能测试记录

**测试日期：** 2026-10-25

## 1. 测试环境

| 项目 | 配置 |
|---|---|
| 系统 | WSL Ubuntu 24.04 |
| CPU | Intel Core i5-9400，6 核 6 线程 |
| 构建配置 | CMake Release |
| 推理框架 | ONNX Runtime 1.21.1 |
| 模型 | YOLO11n ONNX |
| 测试视频 | test.mp4，共 150 帧 |
| 队列容量 | 200 |

本报告记录当前 CPU 推理实验。结果用于项目内部对比，不代表其他硬件上的性能保证；本轮不包含 TensorRT 性能结果。

## 2. 计时口径

- **Pipeline FPS**：整条视频处理流水线的吞吐率，包含读取、推理和结果显示等流程。
- **ORT Run 延迟**：ONNX Runtime 内部模型执行阶段的耗时。
- **Backend API 延迟**：调用后端推理接口的总耗时，范围比 ORT Run 更大。
- **Preprocess 延迟**：图像复制和预处理所花费的时间。
- **Postprocess 延迟**：输出解析、NMS 和结果绘制所花费的时间。
- **P50 / P95**：分别表示第 50 和第 95 百分位延迟。

每次测试前先使用 640×640 图像进行 5 次预热；预热不计入正式计时和 Benchmark 样本。

## 3. 线程数初筛

保持模型、视频和其他测试条件不变，调整 ONNX Runtime intra-op 线程数。以下为单次筛选结果：

| 线程数 | Pipeline FPS | ORT 平均延迟（ms） | ORT P95（ms） |
|---:|---:|---:|---:|
| 1 | 6.69 | 134.93 | 151.93 |
| 2 | 8.76 | 96.91 | 107.10 |
| 3 | 9.98 | 83.38 | 93.65 |
| 4 | 10.23 | 79.82 | 114.81 |
| 6 | 5.27 | 170.43 | 234.94 |

初筛结果表明，线程数与性能不是简单的正相关关系；使用全部 6 个线程反而出现明显退化。单次实验只能用于筛选，不能据此认定最优线程数。

## 4. 3 线程与 4 线程复测

交替运行，每个线程配置测试 3 次。表中是 3 次运行各自统计结果的算术平均：

| 线程数 | Pipeline FPS | ORT 平均延迟（ms） | ORT P95（ms） |
|---:|---:|---:|---:|
| 3 | 10.02 | 82.63 | 109.82 |
| 4 | 9.69 | 85.63 | 124.69 |

这组复测中，3 线程整体表现略好，因此当前默认值设为 3。不过运行间存在波动，样本数量也有限，不能认为 3 线程在所有环境下都优于 4 线程。

## 5. 当前默认配置基线

在默认 3 线程配置下，连续运行 3 次。下表为每次运行的统计量再取算术平均，不是将 450 个样本合并后重新计算的结果。

| 指标 | 3 次运行的平均值 |
|---|---:|
| Pipeline FPS | 9.86 |
| ORT 平均延迟 | 84.11 ms |
| ORT P50 | 77.87 ms |
| ORT P95 | 104.65 ms |
| 预处理平均延迟 | 14.63 ms |
| Backend API 平均延迟 | 84.54 ms |
| 后处理平均延迟 | 1.31 ms |

预处理平均耗时约 14.63 ms，后处理约 1.31 ms，而 Backend API 平均耗时约 84.54 ms。当前主要耗时位于后端推理调用阶段，后续优化应优先围绕推理执行和数据传递展开。

不同运行中的 Pipeline FPS 在约 9.40 至 10.44 之间波动，且存在偶发的高延迟样本。因此后续比较必须保持相同测试条件，并尽量重复运行。

## 6. 追加连续复测（2026-10-25）

在 Release 构建、默认 3 个 intra-op 线程、5 次预热的条件下，追加运行了 3 次完整视频测试。每次均成功读取、推理和显示 150 帧，进程退出状态为 0。

| 次数 | Pipeline 耗时（秒） | Pipeline FPS | ORT 平均（ms） | ORT P95（ms） | 预处理平均（ms） | Backend API 平均（ms） | 后处理平均（ms） |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 18.1101 | 8.28269 | 94.994 | 176.546 | 21.698 | 95.972 | 1.354 |
| 2 | 17.8481 | 8.40424 | 98.503 | 174.154 | 16.843 | 99.015 | 1.393 |
| 3 | 15.8719 | 9.45066 | 88.542 | 102.481 | 14.475 | 88.972 | 1.231 |
| 三次结果的算术平均 | 17.2767 | 8.71253 | 94.013 | 151.060 | 17.672 | 94.653 | 1.326 |

说明：平均行是对每次运行对应的统计值取算术平均，并非将 450 个单帧样本合并后重新计算。平均 P95 仅用于比较这三次运行，不代表合并样本的整体 P95。

本组三次的 Pipeline FPS 约为 8.28–9.45，ORT P95 约为 102.48–176.55 ms，存在可见波动。不同运行之间的差异不能简单归因于代码变化；CPU 负载及其他运行环境因素也可能产生影响。

因此，保留先前基线作为历史记录，并把本组数据作为追加复测。后续进行性能优化比较时，应尽量固定测试条件、重复运行并同时观察平均延迟与 P95。

## 7. 当前结论与后续计划

1. 当前 CMake 构建配置已确认是 Release。
2. 已为 Pipeline 增加预热，避免把首次运行的初始化开销混入正式统计。
3. 已分别统计预处理、后端调用和后处理耗时。
4. 当前默认 intra-op 线程数为 3，可通过环境变量 `YOLO_ORT_INTRA_OP_THREADS` 调整；修改后应重新实测。
5. 后续应进一步验证瓶颈，评估预处理开销、线程配置和推理后端差异。GPU 与 TensorRT 的性能需要单独测试，不能用本报告的 CPU 数据推断。

# 小样本真实精度补验（2026-11-12）

## 已完成

使用Ultralytics官方COCO8 v0.0.0压缩包（443158字节，SHA-256见机器摘要）中的4张val图和17个真实标注框，分别用现有FP32及INT8模型执行原生C++预测导出。用官方pycocotools 2.0.10复核同一批预测，和本项目限定non-crowd评估器的结果差异不超过1.2e-16。新增固定种子的官方参考交叉验证及浮点召回网格回归测试。

| 模型 | AP50 | AP75 | mAP50–95 |
|---|---:|---:|---:|
| FP32 | 0.855938 | 0.715347 | 0.603858 |
| INT8 QDQ | 0.930418 | 0.572018 | 0.623146 |

这是同一组4图的真实标注回归。INT8的AP50和mAP增加，但AP75下降约0.1433，不能写成量化无损或整体精度提升。没有因此推翻此前CPU INT8变慢的性能记录。

## 修正的问题

旧评估器为召回比较加了1e-12容差，且用step/100构造网格。这与官方NumPy linspace/searchsorted的浮点边界不完全一致：例如0.70网格可为0.7000000000000001，不能人为把它视为恰好7/10。真实数据中，人员类别在IoU 0.55/0.60上出现小偏差。现按相同网格与严格左侧查找处理，版本为bbox-101point-noncrowd-v2。此前v1合成测试通过不代表已经和官方实现交叉验收。

## 数据与结论边界

- 官方说明COCO8来自COCO train2017，4张train、4张val；这里仅用其中val4图。它是快速流程检查集，不是COCO val2017全量测试，也不能保证未参与模型预训练。
- 验证输入张量与已有INT8校准报告中的张量SHA-256交集为0，证明本轮按该预处理得到的图片内容未与所记录校准张量完全重复；不证明任意近似场景、相邻帧或模型训练数据完全独立。
- 导出分数阈值0.001、按类NMS IoU 0.45，沿用原程序整数框。两个模型和校准报告均核对身份。
- 限定评估器仍不实现crowd/ignore、面积分组或segmentation；正式COCO结果以官方COCOeval为准。
- 大规模独立测试集与跨场景泛化仍未验收，不能把这4张图的结果写成普适模型精度。

## 复现

在项目量化虚拟环境内安装requirements-evaluation.txt；不会安装系统软件。COCO8官方来源：https://github.com/ultralytics/assets/releases/download/v0.0.0/coco8.zip 。只需约443KB，不下载模型。解压后保留其中LICENSE与README；数据和图片留在results，不纳入Git。

```bash
.venv-quant/bin/python -m pip install -r requirements-evaluation.txt
.venv-quant/bin/python tools/validate_coco8.py --dataset results/2026-11-12-finalization/coco8 --fp32 models/yolo11n.onnx --int8 results/2026-11-09/quantization-final/model.int8.onnx --calibration-report results/2026-11-09/quantization-final/report.json --output results/new-coco8-evaluation
```

新clone没有模型、校准报告和数据，须先按已有量化文档准备，不会由测试隐式下载。验证工具拒绝覆盖旧输出目录。原始预测、标注转换和日志在本地results/2026-11-12-finalization，公开只提交汇总和文件身份。

pycocotools来自官方PyPI，所用cp312 abi3 x86-64 wheel SHA-256已与PyPI元数据核对，许可证副本见docs/licenses/pycocotools-LICENSE。COCO8原归档的AGPL许可证保存在本地，未把归档或其图片再分发进项目。

官方数据说明：https://docs.ultralytics.com/datasets/detect/coco8/ 。
